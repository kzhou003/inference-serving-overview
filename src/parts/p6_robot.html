11机器人推理：从“吞吐”回到“实时”

机器人策略模型（VLA，Vision-Language-Action）在结构上是“VLM + 动作头”，看起来像多模态 LLM，但推理的目标函数完全不同：它运行在一个物理闭环里，延迟和抖动直接决定任务成败与安全，而吞吐几乎无所谓。

代表模型

模型结构推理相关特点
RT-2（Google DeepMind，2023）大 VLM 直接输出离散化动作 token模型很大，控制频率只有个位数 Hz，依赖云端
OpenVLA（2024）7B，Llama-2 骨干，自回归输出动作 token每个动作维度一个 token，逐个生成，频率低
π0 / π0.5（Physical Intelligence）PaliGemma 3B VLM + 约 3 亿参数的 action expert，flow matching一次推理输出 50 步的动作块（action chunk），用约 10 步积分生成连续动作，支持 50 Hz 控制
GR00T N1 系列（NVIDIA）System 2：VLM 理解（约 10 Hz）；System 1：DiT 动作头（flow matching）快慢双系统；面向人形机器人，部署到 Jetson Thor
Helix（Figure）S2：7B VLM，7–9 Hz；S1：约 8000 万参数视觉运动策略，200 Hz双系统解耦，S1 用 S2 的最新潜变量

机器人推理 vs LLM serving

维度LLM serving机器人推理
闭环开环：生成完交给用户闭环：动作改变世界，下一帧观测依赖上一步动作；推理慢 = 用过期的观测做决策
批大小越大越好每台机器人 batch = 1（机队云端推理时可以跨机器人拼批）
关心的统计量p50 / p99 延迟、吞吐最坏情况延迟、抖动、是否错过控制周期
硬件数据中心 GPU机载边缘设备（Jetson Orin / Thor，功耗几十到上百瓦）或经 Wi-Fi / 5G 访问远端 GPU（网络抖动）
频率按请求多速率：VLM 推理 5–10 Hz，动作策略 50–200 Hz，底层关节控制 500 Hz–1 kHz
失败代价重试即可不能重试，可能造成碰撞；需要看门狗、动作限幅、超时回退
输入文本 / 图片多路相机流 + 本体感觉（关节角、力矩），持续不断

关键技术

  • Action chunking（ACT，2023）：一次推理预测未来 H 步动作，降低推理频率要求；相邻块重叠部分用 temporal ensembling 平滑。π0 系列用 50 步的块。
  • 异步推理：执行当前块的同时就开始推理下一块，机器人不需要停下来等模型（LeRobot 的 PolicyServer + RobotClient 架构，SmolVLA 论文中提出）。
  • Real-Time Chunking（RTC，Physical Intelligence 2025）：异步时新块和正在执行的块会“接不上”。RTC 把生成新块看作 inpainting：推理延迟期间必定会执行的动作被冻结，其余部分被引导与之衔接，在不重新训练的前提下得到平滑连续的动作。
  • 快慢双系统：把慢的语义理解和快的运动控制解耦，各自按自己的频率运行（Helix、GR00T）。
  • 压缩与编译：INT8 / FP8 / INT4 量化、TensorRT 引擎、更少的 flow 积分步、蒸馏小策略；batch = 1 时 kernel launch 开销占比高，CUDA graph / JAX jit 很关键。
  • 远程推理：机器人只做传感与控制，策略跑在附近的 GPU 上（openpi 用 websocket 提供策略服务）；要处理网络抖动和断连回退。
  • 仿真与世界模型：训练和评测依赖大规模 GPU 仿真（Isaac Sim / Isaac Lab）和视频世界模型（NVIDIA Cosmos 等），它们本身也是推理负载（大批量、扩散生成）。
