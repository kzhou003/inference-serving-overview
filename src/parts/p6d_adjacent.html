Sandbox：让模型生成的代码和动作安全地执行

Agent 会写代码、跑命令、开浏览器；RL 训练需要几千个并发环境跑单元测试。这些代码不可信，必须在隔离环境里执行。sandbox 已经成为 agent 产品和 RL 基础设施的标准组件。

隔离技术原理启动 / 开销隔离强度谁在用
容器（Docker）Linux namespace + cgroups，共享宿主内核最快、最省最弱（内核漏洞可逃逸）受信任代码、内部 RL 环境
gVisor用户态内核拦截系统调用较快，系统调用密集型负载有开销中高Modal、Google Cloud Run

OpenSandbox（阿里开源）每个 sandbox 是一个 OCI 容器，注入 Go 写的执行守护进程 execd 负责命令、文件、代码执行；统一的 sandbox API + 多语言 SDK + MCP serverDocker 本地 / Kubernetes 集群运行时，可接入更强隔离的容器运行时取决于底层运行时coding agent、GUI agent、agent 评测、RL 训练环境

  • 关键需求：冷启动（预热池、快照 / 恢复、CRIU）、密度（单机几百上千个）、网络出口控制、文件系统持久化与暂停 / 恢复（长时 agent 会话）、资源限额与超时、可观测性。
  • 开源平台：OpenSandbox（阿里开源，仓库现位于 opensandbox-group 组织）提供统一 sandbox API、Python / Java / JS / C# / Go SDK、CLI 与 MCP server，并带有 Claude Code、Gemini CLI、Codex CLI 等 coding agent 的接入示例；E2B 也开源了 SDK 与基础设施代码。
  • 服务商：E2B、Modal Sandboxes、Daytona、Runloop、Northflank、Cloudflare Sandbox / Containers、Vercel Sandbox 等；模型厂商自带的代码执行工具（OpenAI Code Interpreter、Anthropic code execution tool）。
  • 开源：Firecracker、gVisor、Kata；面向 agent 的运行时如 OpenSandbox、OpenHands runtime、SWE-ReX。

API 网关、模型路由与缓存

  • 统一网关：LiteLLM（开源代理，统一上百家供应商的 OpenAI 兼容接口）、OpenRouter（模型市场与路由）、Portkey、Kong AI Gateway、Envoy AI Gateway、Cloudflare AI Gateway。负责鉴权、按 token 限流（TPM / RPM）、配额、计费、重试与 fallback。
  • 模型路由：按问题难度选模型以省钱（RouteLLM、vLLM Semantic Router）；按地域、价格、延迟选供应商。
  • 缓存：精确缓存、语义缓存（向量相似度命中，需谨慎）、供应商侧的 prompt caching。
  • 多租户安全：前缀缓存可能被用作跨租户的时序侧信道（命中更快），可以按租户加 cache salt 隔离（vLLM 支持 cache_salt）。

模型加载、分发与冷启动

  • 格式：safetensors（可 mmap、零拷贝、无反序列化风险）、GGUF（llama.cpp）。
  • 加速加载：Run:ai Model Streamer、fastsafetensors、CoreWeave tensorizer、GPUDirect Storage；权重预置到节点本地 NVMe；节点间 P2P 分发（如 Dragonfly）。
  • 镜像：推理镜像动辄几十 GB，用懒加载镜像（eStargz、Nydus）或预拉取。
  • 快照：进程级 / GPU 显存级快照恢复，把“加载 + 编译 + 预热”的分钟级冷启动压到秒级。

安全与合规

  • 内容安全分类器（Llama Guard、ShieldGemma、NeMo Guardrails）与主模型并行或流式运行，避免串行增加延迟。
  • Prompt injection 防护（尤其 agent 读取外部内容时）、PII 脱敏、日志留存策略。
  • 机密计算（H100 / Blackwell 的 Confidential Computing 模式）用于敏感数据推理。
